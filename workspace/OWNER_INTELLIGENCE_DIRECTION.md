# ASHWOOD Workspace — Owner Intelligence Direction

Workspace is not a text dashboard. It is a private owner-intelligence surface.

## Design rule

- Meaningful visuals first.
- Words are sparse and high-signal.
- Analysis is grounded in live Workspace evidence and owner goals.
- Static hero copy is discouraged. The hero should rotate or react to evidence, time, owner input, or other trusted personal context.
- Reflection language must not present spiritual systems, astrology, Human Design, or affirmations as factual prediction. They can be used as reflective lenses when explicitly selected or supplied by the owner.

## Hero

The hero is a living **Owner signal**. It can rotate between:

1. evidence-derived pattern analysis,
2. an owner-supplied reflection/affirmation,
3. a compact question that helps distinguish motion from progress.

The current first source includes the owner's supplied Stella / Human Design reflection about allowing information to gather rather than forcing clarity.

## Visual intelligence

The page should progressively replace verbose explanations with visual relationships:

- goals → evidence volume / momentum,
- projects → goals connection field,
- 14-day rhythm,
- workstreams → next gates,
- attention → gaps / contradictions,
- owner signal → synthesis across those systems.

Details remain available on demand rather than occupying the default visual hierarchy.

## Truth boundary

"Real-time analysis" means analysis of currently available Workspace evidence and connected product state. Missing evidence must be shown as missing; ASHWOOD must not invent confidence, activity, or personal insight to make the interface feel intelligent.
