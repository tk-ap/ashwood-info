How OmniChat connects

This is a static design prototype. Sample swim lanes are deliberately marked Demo data. Use the Connect feed control only when this route is hosted behind an authenticated AgentOS read-only telemetry bridge.

The bridge must serve GET /api/omnichat/activity with observed_at, lanes[], heartbeat timestamps, and durable lifecycle evidence. The write path is separately governed: POST /api/omnichat/command through AgentOS and LEDGATo, never direct harness execution.

21st.dev references: Agent Elements (chat/tool states) and Agent Activity (collapsible activity timeline). Design recreated for the existing ASHWOOD direction, no third-party runtime scripts.
