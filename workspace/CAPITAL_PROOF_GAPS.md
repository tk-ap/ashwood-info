# Capital → Proof Gap Map — 2026-09-18

## Purpose

ASHWOOD sponsorship/investor work should not invent projects that need money. The operating question is:

> **Where is a zero-dollar constraint preventing the ecosystem from producing the next piece of viability evidence?**

Capital is useful only when it can be connected to a specific proof gap, a bounded use of funds, and evidence that materially changes what we know.

This is the source of truth for investor-facing funding needs. It is not a generic fundraising wishlist.

## Evidence hierarchy

Prioritize gaps that block evidence in this order:

1. real customer / organizational usage;
2. repeated voluntary usage;
3. measurable before/after product effect;
4. external independent execution or enforcement proof;
5. infrastructure hardening required for a real pilot;
6. acquisition/distribution experiments with measurable conversion;
7. convenience, polish, or speculative feature expansion.

Money should not be requested for work that can still be completed credibly with existing infrastructure.

## ALVIRA — highest commercial proof burden

**What already exists:** working product loop; Founding Beta infrastructure; guided interview; Context creation; review/correction; reuse/Bridge surfaces; Context Lift measurement framework; organizational Design Partner / POC protocol.

**What is not proven:** that persistent user-controlled Context creates enough recurring value for individuals or organizations to keep using it and pay for it.

**Current zero-dollar diagnosis:** the canonical evidence plan does **not** show a technical paywall preventing the next experiment. The immediate bottleneck is access to real users/design partners and completed experiments, not paid infrastructure.

**Investor-use-of-funds trigger:** capital becomes a legitimate proof unlock when a specific acquisition, participant-compensation, research, integration, compliance, or pilot cost is required to obtain evidence that cannot be obtained credibly for free.

**Do not pitch:** “money to finish ALVIRA.” The product exists. Pitch capital against accelerating/measuring validated usage only when the incremental cost is concrete.

## ailhat — customer activation proof

**What already exists:** tenant-isolation and Founding Beta/commercial rails plus an evidence architecture spanning production, repository, deployment, history, and eventually market signals.

**What is not proven:** that a new customer can independently complete the canonical activation loop and find enough portfolio intelligence valuable to return/pay.

Canonical unassisted proof:
`invite → account → add first product → establish production URL → first observation/scan → understand what deserves attention → choose a decision → prepare/direct work → verify the change`

**Current zero-dollar diagnosis:** no documented cash requirement blocks the first controlled beta. The repo explicitly says the next validation lane is a deliberately small cohort after isolation checks.

**Investor-use-of-funds trigger:** a real cost required to recruit/compensate the cohort, connect evidence sources unavailable under current free limits, or operate the product at a scale needed to test repeat use.

**Do not pitch:** infrastructure spend before the first-user loop has been tested.

## ledgato — external enforcement / production-hardening proof

**What already exists:** ALLOW/DENY/APPROVE, approval/resume, delegated/JIT authority, GitHub/HTTP adapters, verification/readback, signed evidence, SDK/API, CI denial proof, independent live GitHub attack-family verification.

**What remains:** real external pilot restart testing; governed-harness fail-closed/no-bypass behavior on outage/error; fresh-repository E2E under explicit authorization; production-hardening beyond the current single-process/file-backed pilot model; minimum-scoped production credential practices.

**Current zero-dollar diagnosis:** some remaining proof can be supplied by a design partner's authorized environment rather than cash. Multi-writer production persistence, secret-management/rotation, durable hosting, or independent external verification may eventually create real paid requirements.

**Investor-use-of-funds trigger:** when a named external pilot requires paid hosting, persistence, secret custody, security review, or independent verification that cannot be supplied in-kind.

**Strong capital story if triggered:** capital closes the distance between verified lab enforcement and production-grade external evidence. Quote the actual gap; do not imply the lab proof is absent.

## AgentOS / ALVIRA Workforce — autonomy proof

**What already exists:** governed task routing/control-plane architecture; Hermes scheduled dispatcher; live subscription-backed Codex and Claude execution fixtures; checkpoint/handoff and boundary tests; execution enters review rather than automatically claiming completion.

**What remains:** proof on meaningful real objectives that autonomous routing/recovery reduces founder coordination burden while preserving verification and authority boundaries.

**Current zero-dollar diagnosis:** existing local/subscription-backed execution is enough for more proof. The verification record explicitly lacks monetary-cap telemetry, but that alone is not a reason to raise money.

**Investor-use-of-funds trigger:** a selected external workload exceeds available capacity or requires paid compute/models/observability/independent verification to run a rigorous repeated trial.

**Do not pitch:** generic “agent compute.” First exhaust the proof available through existing capacity and measure where capacity actually stops the experiment.

## ASHWOOD distribution / founder runway

There is one broader constraint the product repos cannot measure by themselves: founder time and personal runway.

This may be economically decisive, but it must not be disguised as a product infrastructure expense. If fundraising is intended partly to create enough runway for TK to continue full-time evidence collection, say so directly and model the amount separately from product proof costs.

Investor framing should distinguish:

- **product proof capital** — money directly buys an experiment/infrastructure/input that produces evidence;
- **distribution capital** — money buys access/recruitment/channel testing that produces demand evidence;
- **founder runway** — money buys time to continue executing the evidence program.

Do not mix these into one vague “development” number.

---

## Capital readiness gate

A pain point can enter investor material only when:

1. the missing viability evidence is named;
2. the zero-dollar constraint is demonstrated rather than assumed;
3. the cheapest credible way to close it is identified;
4. the amount is based on an actual quote/budget;
5. the experiment has a pass/fail or learning criterion;
6. we can explain what becomes knowable after spending the money.

If free/in-kind execution can still answer the question, run that first.

## Current conclusion

The ecosystem is **not presently blocked everywhere by lack of capital**. Several of the highest-value next proofs are still executable with existing infrastructure and require users, partners, disciplined experiments, and measurement more than cash.

The investor case should therefore be built from **specific places where free execution eventually breaks**, not from a broad claim that funding is needed to continue building. This document should be updated whenever a proof attempt stops specifically because a paid resource is unavailable.
